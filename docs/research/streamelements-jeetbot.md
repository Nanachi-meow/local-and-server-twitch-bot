# Ресёрч: StreamElements + JeetBot как источник идей для twitch-bot

Дата: 2026-11-16. Автор: фича-исследователь (саб-агент).

Задача: изучить публичные доки StreamElements (docs.streamelements.com) и JeetBot
(jeetbot.cc, docs.jeetbot.cc) **только как источник идей поведения**. Код и ассеты не
копируются, всё описано своими словами по публичной документации. Цель — таксономия
фич, реализуемых в нашем стеке: чистый Node.js 22+ без зависимостей, официальные
API Twitch (Chat Bot API + EventSub WebSocket), локальный оверлей для OBS по SSE.

Что у нас уже есть (база для оценок): оверлей с алертами (SSE, текст+звук,
длительность, «Тест»), баллы за просмотр/активность, колесо-рулетка, мем-магазин,
кастомные команды с режимами/шансами, таймеры, события с шаблонами, шатауты,
закрепы, анонсы, модули-хуки, до 10 каналов.

Оценки: **легко** (чистый JS поверх существующих хуков/SSE/Helix), **средне**
(неделя-две, новая подсистема, но без внешних препятствий), **тяжело** (крупная
подсистема или протокол), **нельзя** (объективное ограничение стека/архитектуры).

Источники (основные страницы):

- SE: /overlays (AlertBox variations, custom code in alertbox, KappaGen, widget data,
  getting started), /chatbot (modules: duel, songrequest и др.; commands/default;
  variables), /loyalty, /loyalty/stream-store, /media-requests, /getting-started.
- JeetBot: jeetbot.cc (лендинг, список фич), docs.jeetbot.cc: /base-stuff/events,
  /text-to-speech/*, /widget-editor/* (Mod Alerts), /song-requests/* (basic, settings,
  overlay), /category/common (список остальных фич).

## 1. Медиа-алерты — сердце запроса

### 1.1. Как устроено у StreamElements (AlertBox)

Виджет AlertBox в редакторе оверлеев. На **каждый тип события** отдельный набор настроек:

- медиа: статичная картинка, GIF или **видеофайл**;
- звук (свой файл);
- **макет**: текст поверх медиа или текст рядом с ним;
- текст-шаблон со своими переменными события (`{name}` и т.п.);
- **длительность показа** на экране (в секундах).

**Вариации** — главная идея, которой нам не хватает. Одно событие → несколько
вариантов алерта, выбираемых по условию:

- у сабов 3 встроенные вариации: обычный саб, **ресаб**, **подаренный саб**;
- **community gift** (массовый подарок): без этой вариации 10 подарков = 10 алертов
  подряд, с ней — **один сводный** алерт. Паттерн «окно агрегации»;
- свои вариации с условиями: «тип подписки = Prime», сумма доната в диапазоне,
  количество битсов, размер рейда;
- у рейдов можно задать **минимальный порог зрителей** (пусто = срабатывать на все);
- опционально показывать **сообщение зрителя** (sub message) в алерте.

**TTS прямо в алерте**: голос из списка; режим «announce action» — сначала читается
само действие («X подарил саб»), потом текст сообщения.

**Управление из чата**: команда мода `!alerts` — замьютить, пропустить, поставить на
паузу текущие алерты.

**Кастом-код**: продвинутый режим, где алерт — это HTML/CSS/JS с инлайн-переменными:
`{{name}}`, `{{amount}}`, `{{tier}}`, `{{sender}}` (даритель), `{{message}}` (HTML с
картинками-эмотами), `{{image}}/{{video}}/{{audio}}` (URL), `{{videoVolume}}`,
`{{audioVolume}}` (0..1, замьютены = 0), `{{widgetDuration}}` (секунды — для точно
выставленной exit-анимации). Т.е. «длительность» у них — не только «сколько висеть»,
но и «синхронизировать уход с анимацией».

**Widget Data dashboard**: ручная правка того, что показывают лейблы и цели
(«последний фолловер» с опечаткой — исправить без события). Сессионные счётчики,
«топы сессии», авто-сброс сессии через ~15 минут после ухода в оффлайн, агрегаты
за 7/30 дней (скользящее окно или календарные периоды).

### 1.2. Как устроено у JeetBot

**Media alerts** (раздел «Channel» на лендинге) + **события-правила** в дашборде:
`событие → условия → действия`.

События: фоллоу, рейд (условие «зрителей от N до M»), саб, ресаб, подарки,
**первое сообщение зрителя** (период: «этот стрим» или «последние 24 часа»),
**фраза в чате** (точное совпадение или «содержит»).

Условия: роль зрителя, размер рейда, «только пока стрим в эфире», аудитория
(«только из списка», у каждого своё сообщение).

Частота: **глобальный кулдаун** на правило + **персональный кулдаун** на зрителя.

Действия (несколько, исполняются сверху вниз, порядок перетаскивается):
чат-сообщение (доставка «как ответ»), **шатаут**, **медиа-алерт**, **войс-овер (TTS)**.

Важные штрихи поведения:

- если под несколько правил подошло одно событие — **срабатывают все** (для порогов
  советуют непересекающиеся диапазоны);
- **флуд-протекция**: максимум 20 срабатываний в минуту на тип события, лишнее
  молча дропается;
- переменные рейда: `$(user)`, `$(channel)` (ссылка на канал райдера), `$(clip)` /
  `$(clip_title)` — **случайный клип райдера** (топ-100 популярных или свежие за 30
  дней), `$(category)` — во что играли райдеры. Если клипа нет — сообщение с `$(clip)`
  не отправляется, но остальные действия (шатаут и т.д.) выполняются;
- **симулятор правила**: подставной ник, кнопка «симулировать», ничего реально не
  отправляется — проверка правила до стрима;
- готовые шаблоны правил в один клик («Raid: raider clip», «Привет новичку»…);
- тумблер вкл/выкл правила без удаления.

**Mod Alerts** (платная фича, Pro): полноценный **визуальный редактор OBS-сцены** на
холсте 1920×1080 — для стримера и модов. Компоненты: текст (правка двойным кликом
прямо на холсте), картинка/GIF/видео (медиа-библиотека с лимитом файлов), YouTube
(обычная ссылка/Short/embed), **таймер обратного отсчёта**, **QR-код**, звуки из
библиотеки. Слои с глазом/замком и папки, undo/redo, число «редактируют сейчас»,
тулбар компонента (жирный/глаз/шрифт/цвет/тень/громкость), направляющие расстояний,
фон-подложка (кадр стрима / живой стрим / чужой канал) для точной раскладки.
Безопасность показа: **новый элемент полупрозрачен и не идёт в стрим, пока не
включишь видимость**. Интеграция с OBS: список сцен OBS прямо в редакторе,
«виджет по ссылке» (свой сайт), импорт существующего browser-source. Ссылку на
виджет видит только владелец канала; моды редактируют без ссылки; при утечке ссылка
регенерируется.

Сюда же: **BRB-экран** — `!brb 5` вешает на стрим экран с таймером и текстом
(«вернусь через 5 минут»), `!brbstop` снимает; есть кнопка в дашборде и Stream Deck.

## 2. Виджеты оверлея

### 2.1. Что у них

- **Labels** (SE): «последний фолловер/саб», «последний донат» — обновляются сами,
  правятся вручную в Widget Data.
- **Goals** (SE): виджеты-цели «фоллоу-цель», «саб-цель», «цель по донатам/битсам»:
  прогресс-бар, значение цели, автоприрост от событий + ручная корректировка. Цели
  сами не сбрасываются между стримами.
- **Session data** (SE): счётчики сессии и «топы» (крупнейший донат сессии и т.п.);
  сброс автоматически через 15 минут после оффлайна или вручную.
- **KappaGen** (SE): эмоты чата летают по экрану + «эмосплозии». Настройки: размер
  эмота, 5 стилей анимации, сезонные шапки, показ эмотов сообщений (режим «комбо»,
  только сабы, лимит эмотов на юзера в секунду, время жизни), взрывы по чат-событиям
  и по команде `!kappagen`, число эмотов на взрыв, свои кастомные эмоты (в т.ч. по
  regex-триггеру).
- **Chat overlay** (JeetBot): чат поверх игры; шрифт/цвета/тени/направление ленты;
  **OBS-док с модерацией**: свайпом сообщение удалить/выдать таймаут, сообщения,
  придержанные AutoMod, — разрешить/отклонить прямо в доке.
- **Credits** (SE, виджет галереи; отдельной страницы в доках нет): «титры» в конце
  стрима — листающийся список участников сессии (фолловеры, сабы, райдеры, топ
  чата). Поведение общеизвестно, в доках детально не описано — брать идею, не детали.
- **Колесо как виджет** (SE): spin-wheel для розыгрышей — крутится, выбирает
  участника/приз. У JeetBot аналога в доках не увидел; у нас колесо уже есть
  как игра на баллы.

### 2.2. Реализуемость у нас

| Фича | Оценка | Комментарий |
|---|---|---|
| Labels «последний X» | **легко** | Статический слой в overlay.html, обновление по SSE. Начальные значения — при загрузке из state |
| Goals (фоллоу-цель и т.п.) | **легко** | Стартовое число фолловеров — Helix (total followers), прирост — наши follow-события; цель и сброс — в настройках. Образец SE: «не сбрасывается сама» |
| Session data / «топы сессии» | **легко** | Счётчики в памяти, сброс по stream.offline + 15 мин. Красиво закрывает «итоги стрима» |
| Credits-титры | **легко/средне** | Собираем участников за сессию (у нас все события уже в шине) → листающийся список в оверлее по команде/кнопке |
| KappaGen-лайт | **средне** | Эмоты сообщения берём из fragments чата (ID эмота → CDN-картинка Twitch, без ключей), полёт/взрыв — CSS/JS. Сезонные шапки и regex — опционально потом. Очень зрелищно за умеренные усилия |
| Chat overlay | **средне** | Новая страница `/overlay/chat`, подписка на тот же SSE. Модерация из дока — у нас панель и так локальная, свайп-модерация — средне (нужны delete/timeout через Helix, они есть) |
| Колесо-виджет розыгрышей (не игра) | **легко** | Рендер колеса в оверлее уже есть; добавить режим «список имён от мода, крутить по кнопке/`!крутить`» |

## 3. Лояльность (аналог SE Loyalty)

### 3.1. Как у них

- очки капают **каждые 10 минут** только тем, кто виден в списке чаттеров;
- бонусы за настраиваемые события: фоллоу, саб, ресаб, донат; **множитель для
  сабов**; исключения (exclude) для отдельных зрителей;
- **имя валюты** настраивается (pointsname);
- лидерборд с тремя вкладками: **Current** (просмотр + мини-игры), **All-Time**
  (только время просмотра), **Watch Time** (минуты);
- команды: `!points` (баланс+ранг), `!top`, `!givepoints` (передать), `!addpoints` /
  `!setpoints` (мод), `!watchtime`, `!leaderboard` (ссылка);
- перенос баллов при **смене ника** — автоматически при первом сообщении под новым
  ником (значит, хранят по user_id);
- жёсткий кап 2^31−1 и только положительные значения;
- watch time растёт только в эфире; свёрнутый чат/фулскрин = зритель выпадает из
  списка = пауза начисления;
- **лидерборд как Twitch Extension** в панели канала (собирает данные только с
  момента установки);
- у JeetBot: **VIP за баллы канала** — выдать/снять/срок VIP через `!vips`-команды.

### 3.2. У нас и что взять

У нас уже есть очки за просмотр (опрос чаттеров) и активность, топ, переводы,
`!дать`. Взять за образец:

| Фича | Оценка | Комментарий |
|---|---|---|
| Имя валюты (pointsname) | **легко** | Одна настройка + подстановка в тексты |
| Бонусы за события (фоллоу/саб/ресаб) + множитель сабам | **легко** | Хуки событий уже есть; аккуратно с фармой (анти-абуз: фоллоу-бонус один раз) |
| Exclude-список | **легко** | Список логинов в настройках |
| `!watchtime` + вкладки «за стрим/всё время» | **легко** | watchedMin уже пишется |
| **Хранение по user_id, а не логину** | **средне, важно** | У нас `points.json` по логину — смена ника = потеря баллов. Хранить id, логин — как поле. Данные чата дают user_id. Миграция: при первом сообщении под новым ником перенос (образец SE) |
| Кап int32 и «только положительные» | **легко** | Клэмп при начислении |
| VIP за баллы (JeetBot) | **средне** | Официальный Helix API выдачи/снятия VIP существует (нужен модератор). Слоты VIP у канала ограничены → расписание авто-снятия по истечении «оплаты» |
| Лидерборд-расширение в панели канала | **нельзя** | Twitch Extension требует публичный HTTPS-хостинг и ревью (см. §11) |

## 4. Магазин за баллы (аналог SE Stream Store)

### 4.1. Как у них

Типы товаров: **SFX** (звук), **Stream Perks** (видеоклип по требованию),
**Access-Code List** (список заранее купленных кодов, выдаётся по одному — по
порядку или случайно, с флагом «можно ли повторно»), **TTS** (озвучка текста
покупателя). Сумма в очках, **количество** (quantity), **глобальный и на-юзера
кулдауны**, категорийный кулдаун. Поле Requirements — собрать доп. данные с
покупателя, они видны в списке выкупов. Выкупы (Redemptions): **история до года,
approve/decline** — ручная модерация исполнения. Публичная страница магазина.
Покупка из чата — кастомная команда с `${redeem item}`. Арматура из чата:
`!openstore`/`!closestore`, `!enablesfx`/`!disablesfx`, `!items` (ссылка). Товар
можно скрыть из публичного магазина, но оставить доступным по команде.

### 4.2. У нас и что взять

Наш мем-магазин — это SFX-подмножество. Взять:

| Фича | Оценка | Комментарий |
|---|---|---|
| Типы товаров: звук (есть), видеоклип, «текст/картинка на экран», TTS | **легко** | У мема уже есть текст+звук; добавить поле «видео/медиа» и тип «текст на экран». Образец — Stream Perks |
| Товар «код из списка» | **легко** | Массив кодов, выдача по порядку/рандом, «одноразовость». Отлично для «промокодов» без платёжек |
| Товар «TTS» | **легко** | После фазы 7: `!ttsсообщение`-покупка озвучивает текст |
| Quantity + кулдауны (глобальный/на юзера) | **легко** | Поля в объекте товара + проверка в покупке |
| Тумблеры товара и «магазин закрыт» (`!закрытьмагазин`) | **легко** | Общий флаг + чат-команда мода. Образец `!openstore/!closestore` |
| Очередь исполнения с approve/decline + история | **средне** | Для «стример исполняет руками» товаров (совет, игра в дуэте…). Вкладка в панели, кнопки |
| Requirements (просить текст при покупке) | **легко** | `!мем название [текст]` — аргумент в выкуп, показывается в панели |

## 5. Игры и дуэли (модули SE)

Как у них (сводно):

- **Duel**: `!duel <ник> [ставка]`, у вызванного **2 минуты** на `!accept`/`!deny`,
  есть `!cancelduel`; итог 50/50; ставка поддерживает сокращения `5k`, `1m`, `50%`,
  `all`, не выше баланса **ни одной из сторон** и не выше настроенного максимума;
  кулдаун модуля. Один вызов одновременно.
- **Roulette** — азарт на очки; **Slotmachine** — слоты с эмотами; **8ball** —
  случайный ответ (у нас уже есть режимом рандом-ответов).
- **Raffle**: `!sraffle` — единственный победитель, `!raffle` — мульти-победитель,
  приз делится (split pot); вход `!join`; `!cancelraffle` мгновенно отменяет.
- **Giveaways**: создаются из дашборда, зрители покупают билеты баллами (`!ticket`).
- **Contests**: prediction-беттинг — зрители ставят очки на исход, победители делят
  банк (`!bet`, `!contest` статус). = наша roadmap-фаза «ставки».
- **Emote Bingo** (угадать эмот с карточки), **Emote Combo** и **Emote Pyramid** —
  автоматические игры на сообщениях чата, без команд.
- **Viewer Queue** (`!queue join`) — очередь «поиграть со стримером», отбор.
- **Votekick** — голосование чата за временный кик.

Реализуемость у нас:

| Игра | Оценка | Комментарий |
|---|---|---|
| Дуэль `!дуэль @ник N` | **легко** | Точная копия поведения SE: окно 2 мин, accept/deny/cancel, кап ставки, 50/50. Плюс анимация дуэли в оверлее (средне, но эффектно) |
| Слоты | **легко** | Три эмота, взвешенные барабаны; у нас уже есть взвешенная механика колеса |
| Раффл `!join` (один/несколько победителей, split pot) | **легко** | Таймер набора + анонс + розыгрыш. Образец: `!sraffle/!raffle/!join/!cancelraffle` |
| Giveaways билетами за баллы | **легко/средне** | `!билет N` + кнопка в панели «разыграть» |
| Contests/ставки | **средне** | Уже в roadmap (фаза 3): открыть вопрос, ставить, итог, делёж банка |
| Emote Combo / Pyramid | **средне** | Парсим эмоты из fragments сообщений; комбо-счётчик + детект пирамиды. Kappagen-лайт делит с этим же парсером |
| Emote Bingo | **средне** | Задание «угадай эмот» + проверка сообщений |
| Viewer Queue | **легко** | Список + команды + отбор модом; полезно для игр со зрителями |
| Votekick | **средне** | Технически можно (таймаут через Helix), но осторожно с злоупотреблениями: порог голосов, кулдаун. Низкий приоритет |
| 8ball | **есть** | Режим «несколько вариантов» в фан-командах |

## 6. Song request (музыка по заказу)

### 6.1. Как у JeetBot (music requests)

Вход: `!sr ссылка|ID|название` или **награда за баллы канала** (текст заказа; при
отказе **баллы автоматически возвращаются**). Команды: `!wrongsong` (снять свой
последний), `!queue`, `!np`; модские: `!sr open/close/play/pause/skip/vol/move`,
`!skipsong`. Настройки: приём вкл/выкл, «только в эфире», «объявлять трек в чат»
(кто заказал), дефолтная громкость; **треков на зрителя ≤ 20**, минимальное время
фоллоу, минимальное число сообщений в чате; **размер очереди ≤ 100**, мин/макс
длительность (по умолчанию 30 сек – 10 мин), минимальные просмотры видео;
автоотказ: лайвы, 18+, дубль в очереди. **Чёрные списки (по 200 записей)**:
зрители, видео, YouTube-каналы, слова в названии. Все тексты бота заменяемые, с
плейсхолдерами `{title}`, `{position}`, `{requester}`, `{limit}`. Оверлей: 4+ стиля
(видео с шторкой, плашка у видео, плашка без видео, винил с прогресс-кольцом,
тикер), подпись (что показывать: название/заказчик/прогресс/время), **блюр видео**
off/soft/strong (и из чата `!sr blur`), тост «новый заказ» ~5 сек с объединением
«…и ещё N», счётчик «в очереди ещё N», «скрывать, когда ничего не играет», режимы
воспроизведения: видео / видео-с-фолбэком-на-аудио / только аудио. Очередь живёт
между стримами; новый оверлей стартует на паузе (музыка только по «Play»).

### 6.2. Как у SE (Media Request)

Тот же скелет + специфика: запросы **бесплатные (за очки) / за донат / оба**;
модерация очереди (Pending Approval); лимиты на юзера отдельно для free/paid;
бэкап-плейлист на пустую очередь; фильтры YouTube (только музыка, блэклист
видео/тегов, автофильтр по рейтингу и просмотрам); цена в очках + **скидка сабам**;
уровень, освобождённый от цены и лимитов; приоритет платных над текущим треком,
цена за секунду; voteskip с порогом; «скип при новом запросе», пауза между видео;
публичная страница очереди; док в OBS (SE.Live) — «не запускать из двух мест»;
разводка звука через мониторинг OBS/VAC.

### 6.3. У нас

Roadmap фаза 5 совпадает с этой моделью. Оценка: **средне** (крупная фича, но без
внешних препятствий): YouTube IFrame API в оверлее, oEmbed для длительности (без
ключа), очередь в data/songs.json, SSE для плеера. Взять за образец поведения:

- набор отказов с **понятными причинами** в ответе бота (длинно/очередь полна/18+);
- лимиты на зрителя и чёрные списки (у нас — без наград канала сначала: только
  команда `!sr` за наши баллы, скидок нет, возврат очков при отказе — да);
- «объявлять трек в чат» и `!np`/`!очередь`;
- стили оверлея «плашка/винил/тикер» и блюр — отложить до v2, сначала «видео+подпись»;
- тост «новый заказ» и счётчик очереди — дёшево и живо;
- «новый оверлей стартует на паузе» — правильное поведение для перезапуска OBS.

Нельзя у нас из этого раздела: приоритет за донат и цена за секунду — нет платёжек.

## 7. TTS

### 7.1. Как у JeetBot

Озвучка сообщений чата. Триггеры: **награда «Highlight my message»** (читаются
автоматически), кастомная TTS-награда, **префикс** `!!!` (заменяемый; цена в баллах
канала по группам: все/сабы/VIP/моды), `!!!#голос текст` — голос на одно сообщение.
Персональный выбор голоса: `!tts <голос>`, сброс `!tts default`, список — `!tts
list`. Управление: `!tts_switch`, `!tts_all on|off [10m|1h|2h30m]` (озвучивать весь
чат, временно), `!tts_free sub|vip|mod`, `!ttsignore @ник [1h|1d]`, `!ttsunignore`,
`!ttsusage` (сколько осталось), `!setvoice @ник голос` (мод). **Фильтр мата и
запрещённых слов применяется до синтеза**. Управление из OBS: кастомный **док** в
OBS (пауза/скип/реплей, очередь) + отдельный «плеер» в browser-source для разводки
звука на свой аудио-трек. Лимиты сообщений в день — по тарифам, базовые голоса
бесплатны, при исчерпании — фолбэк-голос. Голоса — в т.ч. «персонажные» (мемы),
это их серверный синтез.

У SE TTS скромнее: голос в настройках алерта + озвучка выкупов магазина.

### 7.2. У нас

Движок — браузерный **speechSynthesis** в оверлее: бесплатно, локально, без
зависимостей (фаза 7 roadmap). Русские голоса есть в Windows/браузерах, но набор
зависит от ОС — «персонажных» голосов не будет (см. §11).

| Фича | Оценка | Комментарий |
|---|---|---|
| Озвучка событий алертов | **легко** | Очередь фраз в overlay.html |
| Префикс `!!!` / команда `!ттс текст` с ценой в **наших** баллах | **легко** | Списание в моменте; группы «все/сабы/VIP/моды» — у нас роли уже известны |
| Персональный голос + `!ттсигнор @ник [время]` | **легко** | Соответствие логин→голос в points-подобном JSON |
| Фильтр мата до озвучки | **легко** | Список слов, маскирование |
| Пауза/скип/реплей из «дока» | **легко** | OBS умеет custom browser docks: наша панель локальна, добавить компактный dock-режим страницы |
| Триггер «награда канала» | **средне** | После фазы 6 (redeption events) |
| Персонажные нейро-голоса | **нельзя** | Облачный сервис JeetBot; локально системные голоса только |

## 9. Альтернативы донатам (наш случай — вообще без платёжек)

SE/JeetBot завязаны на донаты (tipping, SE Pay, приоритет платных заказов, мерч).
Наш эквивалент «внимания за деньги» — три легальных рельса Twitch + наши баллы:

1. **Биты (cheer)** — зритель платит Twitch, мы только красиво реагуем: алерт
   «биты-события» с вариациями по количеству, топ-битсеры сессии, TTS сообщения.
   EventSub cheer-событие доступно боту-модератору. Оценка: **средне** (одно
   событие + вариации алертов).
2. **Баллы канала (награды)** — «донат» без денег: выкуп награды = триггер действия
   (TTS, мем, звук, сцена). Фаза 6 roadmap. Оценка: **средне** — самое близкое к их
   «tipped»-механике, только валюта — баллы канала Twitch.
3. **Хайлайт-сообщение** (стандартная награда) → TTS/алерт — как у JeetBot.
   Оценка: **средне** (нужен redemption-хук).
4. **Наши баллы** — весь магазин/игры уже построены на них; добавить «виртуальные
   чаевые»: `!чаевые N` — перевод баллов стримеру с алертом-благодарностью
   (**легко**, забавно, анти-донат по смыслу).

Паттерн поведения, который стоит перенести из их донат-логики без денег:
**вариация алерта по размеру** (у нас — по числу баллов/битсов), «топы сессии»,
«announce action» перед TTS.

## 10. Что НЕЛЬЗЯ у нас — объективно, и почему

1. **Всё платёжное**: донаты/чаевые, приоритет платных заказов музыки, «цена за
   секунду», платные TTS-лимиты, мерч-розыгрыши Fourthwall. Причина: наш бот —
   локальный процесс на 127.0.0.1 без публичного домена и вебхуков; приём платежей
   требует платёжного провайдера и публичного бэкенда, Twitch не даёт ботам
   принимать деньги. Это ядро бизнеса SE/JeetBot, физически не переносимое в наш
   стек без нарушения «локально и без чужих серверов».
2. **Облачные «магии» JeetBot**: персонажные TTS-голоса (их серверный синтез),
   автоперевод чата, Shazam, RU→EN субтитры на стриме, AI-анализ зрителей,
   премиум-иконки. Всё это исполняется на их бэкенде (часто платном). Локально без
   зависимостей и API-ключей воспроизвести нельзя: speechSynthesis даёт только
   системные голоса, а нейро-синтез/перевод/Shazam требуют внешних платных сервисов.
3. **Публичные страницы для зрителей и совместный удалённый доступ**: публичный
   магазин/лидерборд/очередь музыки (страница с токен-ссылкой), лидерборд-расширение
   в панели канала (Twitch Extension: HTTPS-хостинг + ревью), редактирование сцены
   модами из интернета в реальном времени, стрим-док для мода с другой машины.
   Причина: сервер слушает только 127.0.0.1 — зрители и чужие моды физически не
   могут открыть страницу; расширения и коллаб требуют публичного хостинга. Это
   архитектурное «нельзя», а не деталь реализации.

Сюда же мелочи: висперы (Twitch отдаёт их только верифицированным ботам — уже
отмечено в README), мультиплатформенность Kick/VK/YouTube (мы — только Twitch API).

## 11. Приоритетный топ (ценность/усилие, по мнению исследователя)

1. **Вариации алертов с условиями + медиа (gif/video) в алерте** — средне.
   Прямое усиление готового оверлея, образец SE.
2. **Правила событий в стиле JeetBot** (условия + цепочка действий + два кулдауна +
   симулятор) — средне. Заменяет «шаблоны» на «движок», включает «первое сообщение
   за стрим» и «фраза в чате» как триггеры.
3. **Дуэль + раффл `!join` + слоты** — легко. Геймификация на готовых баллах,
   образцы поведения SE точны.
4. **TTS: префикс/цена в наших баллах/голос на юзера/игнор/док-кнопки** — легко.
   Максимум смеха за минимум кода (speechSynthesis).
5. **Song request по модели JeetBot (лайт-оверлей + отказы с причинами + возврат
   баллов)** — средне. Фаза 5, самая «сочная» зрительская фича.
6. **Магазин: типы товаров (клип/код/текст/ТТС), quantity и кулдауны,
   `!закрытьмагазин`** — легко. Расширение мем-магазина по образцу Stream Store.
7. **Goals + labels + «топы сессии» в оверлее** — легко. Дёшево, зрелищно, SSE уже
   есть; стартовое число фолловеров — Helix.
8. **Kappagen-лайт (эмоты летают + взрывы по событиям и `!каппа`)** — средне.
   Парсеры эмотов потом переиспользуются для combo/pyramid.
9. **Хранение баллов по user_id** — средне, но честность данных важнее новых фич
   (смена ника сейчас теряет баллы).
10. **BRB-экран + `!brb N`** — легко; «док» OBS для панели — легко.
11. **Channel points → действия (фаза 6)** — средне; наш «аналог донатов».
12. **Счётчики и `$(customapi)`** — легко; расширяет команды почти бесплатно.

Не сейчас (тяжело/спорно): полноценный канвас-редактор сцен, OBS WebSocket-контроль
(фаза 8 — свой мини-WS-клиент), нюк, votekick.
