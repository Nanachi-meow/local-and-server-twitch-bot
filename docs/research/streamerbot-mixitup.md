# Исследование фич: Streamer.bot и Mix It Up

> Источник идей для нашего Twitch-бота (`Z:\Проекты\twitch-bot`).
> Чистый Node.js 22+ без зависимостей, официальный Twitch Chat Bot API + EventSub WebSocket,
> локальная страница-оверлей для OBS.
>
> **Правила:** код не копируется — только поведение, пересказанное своими словами по публичным докам.
> Для каждой фичи: как это устроено у них → реализуемость у нас (легко/средне/тяжело/нельзя) → ценность.
>
> Источники: docs.streamer.bot (Guide: Actions, Triggers, Variables, Commands, Quotes, Timers, Credits,
> HTML Overlay, Platforms/Twitch, Stream Apps/OBS; API: Triggers, Sub-Actions),
> mixitup.bot/docs (Commands, Events, Actions, Consumables, Overlays, Games, Quotes, Giveaways,
> Game Queue, Music Player, Moderation, Users, Chat, Platforms/Twitch, Special Identifiers, TTS-экшены,
> OBS-интеграция). Дата исследования: 16.11.2026.

## 0. Контекст нашего проекта (что уже есть)

Из README/ROADMAP: кастомные команды (режимы: текст/варианты/рандом-число с диапазонами, права, кулдауны,
счётчик вызовов), шатауты, закрепы, анонсы, реакции на события (фоллоу/саб/ресаб/подарок/рейд),
таймеры (4 режима срабатывания), баллы (просмотр + активность), колесо-рулетка с весами и множителями,
мем-магазин (алерты за баллы), оверлей (SSE + звуки + анимации), мультиканальность (до 10),
модули с горячей перезагрузкой, панель на localhost.

Лимиты Twitch, которые уже учтены и продолжают действовать:
- ~20 сообщений / 30 с для неверифицированного бота (100/30 с для бота-модератора);
- шатаут: 1 раз / 2 мин на канал, 1 раз / час на человека;
- закреп из чата `!pin` — 20 минут (эндпоинт Send Chat Message);
- ви́сперы недоступны без верификации бота.

**Ключевой архитектурный факт, всплывший при исследовании** (важен для фаз 6 и «Twitch-ивентов»):
ряд EventSub-подписок авторизуется **только токеном бродкастера** (стримера): `channel:read:redemptions`
(channel points), `bits:read` (cheer), `channel:read:hype_train`, `channel:read:polls`/`predictions`,
`channel:read:goals`, `channel:read:ads`, charity. Бот-модератор подписаться на них не может —
но канал.follow можно (moderator:read:followers), чат — можно (user:read:chat + ban-скоупы).
Оба больших бота потому и требуют **двойной вход** (Broadcaster + Bot). У нас вход только бота
→ часть фич ниже помечена «нужен опциональный вход бродкастера».

## 1. Как устроены оба бота (в двух словах)

| | Streamer.bot (SB) | Mix It Up (MIU) |
|---|---|---|
| Ядро | Действие = цепочка sub-actions; срабатывает по триггеру, команде, хоткею, войсу, MIDI, файлу | Команда = цепочка Actions; типы команд: чат, событие, таймер, channel points, bits |
| Условия | Права/кулдауны на командах; фильтры-триггеры (диапазоны, текст, чекбоксы) | «Usage Requirements»: роль, кулдауны, валюта, аргументы, порог уникальных юзеров, настройки |
| Переменные | `%user%`, `%target%`, `%args%`, `%random%`, счётчики, глобальные/юзер-переменные | «Special Identifiers» `$username`, `$argX`, `$randomnumberX`, `$top10...`, событийные переменные |
| Логика | Random Action с весами, группы суб-акций, очереди действий (blocking), C#-код | Conditional Action, Random Action, Group/Repeat Action, Counter/Special Identifier Action, C#-скрипты |
| Данные | Viewers-база (view time, счётчики), data stores, глобальные переменные | Users-база: watch time, сообщения, команды, донаты, сабы, страйки, заметки, кастомные титулы |
| Лояльность | Валюты/ранги — нет встроенных (community-импорты) | Встроены: Currency, Rank, Inventory+Shop+Trade, Stream Pass, Redemption Store |
| Игры | Нет встроенных (community-импорты) | 18 встроенных шаблонов игр |
| Оверлей | HTML Overlay (окно поверх рабочего стола) + виджеты сообщества | Overlay-сервер в самом боте: endpoints, виджеты (event list, цель, лидерборд, босс, титры...) |
| TTS | Вынесено в отдельное приложение Speaker.bot | Встроено: Windows-голоса, Polly, Azure, Google, TTS.Monster, TikTok, Edge |
| OBS | obs-websocket v4/v5 клиент, события, сотни sub-actions | obs-websocket v5 клиент + события |
| Расшаривание | Import/Export в base64-строках, «community imports» | Backup/Restore профиля, «Community Commands» |

Оба бота позиционируют себя как «локальный комбайн». Наша уникальность —
нулевой вес (~40 КБ), без реестра/установки, новый Chat Bot API вместо IRC.

## 2. Системы команд и переменных

### 2.1. Матчинг команд: basic/regex, «начало/точно/в любом месте», алиасы — ЛЕГКО
У SB команда — набор алиасов (строк) + режим: матчить по началу сообщения, точное совпадение или
вхождение в любом месте; плюс режим regex. Кулдауны общие на все алиасы одной команды.
У нас: матчинг по префиксу. Добавить «exact/anywhere/regex + несколько алиасов» — тривиально.
Ценность: средняя (regex — для гиков; алиасы — удобно: `!дискорд` = `!цوتе` = `!social`).

### 2.2. Кулдауны: глобальный + персональный, группы кулдаунов — ЛЕГКО
MIU: Standard (для всех), Per-Person (у каждого свой), Group (общий на пачку команд),
Per-Person Group. SB: Global Cooldown + User Cooldown; бродкастер всегда exempt.
У нас есть один кулдаун на команду. Добавить персональный и групповой — легко (счётчик по юзеру/group id).
Ценность: высокая для игр и спамных команд.

### 2.3. Threshold-триггер: «N разных юзеров за T секунд» — ЛЕГКО
MIU Usage Requirement: команда сработает, только если её вызвали N **уникальных** юзеров
за окно T секунд (и может выполниться для каждого из них или один раз). Это «хайп-фильтр»:
анти-само-спам и групповые ритуалы («3 человека напишут !факт — бот выдаст факт»).
Реализация — счётчик уникальных юзеров с окном. Ценность: высокая, уникальный приём.

### 2.4. Именованные аргументы с типами и «Assign to identifier» — СРЕДНЕ
MIU: обязательные/опциональные типизированные аргументы; аргумент «Cool Name» создаёт
переменную `$coolname`. Плюс `$arg2:5text` (диапазон аргументов) и delimited-аргументы (разделитель `|`).
У нас `{args}` монолит. Диапазоны и `|`-разделитель — легко; именованные поля с UI-редактором — средне.
Ценность: средняя (для «config-команд»: `!ставка открыть вопрос | вариант1 | вариант2`).

### 2.5. Требование «минимум/точное/диапазон валюты» прямо на команде — ЛЕГКО
MIU: команда сама списывает валюту при выполнении (required / min / min-max), проверяет ранг/инвентарь.
У нас списание зашито в коде колеса/мемов. Обобщить: «стоимость» как свойство любой команды — легко.
Ценность: высокая: все кастомные команды становятся платными в один тумблер.

### 2.6. Сообщения об ошибках требований + кулдаун на спам ошибками — ЛЕГКО
MIU: на каждое невыполненное требование — своё сообщение; повторная ошибка того же типа не шлётся
чаще, чем раз в N секунд (глобальный анти-спам). У нас тихое молчание. Добавить «почему молчит»
с кулдауном — легко. Ценность: высокая UX-wise (зрители понимают, что не так).

### 2.7. Counter-переменные и per-user counter — ЛЕГКО (частично есть)
SB: у команды/награды есть общий счётчик (`%counter%`) и пользовательский (`%userCounter%`),
персистентные через рестарты; сброс из контекстного меню. Использование: «этот восклицательный
вызван 137-й раз», лотереи. У нас есть счётчик вызовов. Добавить per-user и переменную — легко.

### 2.8. Персистентные кастомные переменные (глобальные и per-user) — СРЕДНЕ
SB: глобальные переменные (триггер «переменная обновлена»!), user-переменные; MIU: Counter Action
и Special Identifier Action (создать `$myvar` на лету в цепочке). Это «память» бота: состояние игр,
счёт серий, «кто сейчас король». Реализация: JSON-хранилище + подстановка `{var:name}` /
`{uservar:ник}` + хук в модулях. Ценность: очень высокая — фундамент для мини-игр и duels.
Сложность средняя из-за UI-редактора и безопасности подстановок.

### 2.9. Расширенный набор подстановок-переменных — ЛЕГКО
Слить из обоих (по нашим данным это всё считаемо):
- даты/времени: `{дата}`, `{время}`, `{деньнедели}` (MIU $date/$time);
- `{рандом-ник}` — случайный юзер из чаттеров (Helix Get Chatters, аналог `$randomuser`; у SB —
  Get Random User sub-action); ценно для duels/рулеток;
- `{рандом:мин-макс}` — есть; добавить `{ник:без-@}`-хелперы;
- статистика юзера: `{смотрю-время}`, `{собщений}`, `{команд}`, `{последний-визит}`,
  `{акк-возраст}` (Helix /users `created_at`), `{баллы-поз}` (позиция в топе — $user____position);
- стрим: `{зрителей}`, `{чаттеров}`, `{фолловеров}`, `{uptime}` (частично есть);
- юзерские ники для target: `{target}` c автофоллбэком на вызвавшего — есть; MIU target —
  «первый аргумент-юзер или сам юзер», подсмотреть выборку умного
  резолва (если аргумент не ник — таргет = сам юзер). У нас так же.
Ценность: высокая — переменные удешевляют все будущие фичи.

### 2.10. Удаление сообщения-команды после срабатывания — СРЕДНЕ
MIU: Settings-требование «Delete chat commands when run»; SB умеет удалять сообщения.
Нужен bot-moderator scope `moderator:manage:chat_messages` (Delete Chat Message API).
Ценность: средняя (чистый чат во время массовых игр).

### 2.11. «Не отвечать, а действовать»: канал-действия модов из чата — ЛЕГКО
Их slash-команды в окне чата (/ban, /timeout, /clear, /title, /game, /raid, /shoutout, /announce, /vip).
У нас: !announce, !pin, !so уже есть. Добавить чат-команды «!тайтл …» (название), «!категория …»
(Twitch API Modify Channel Information, модератор может менять title/game при разрешении) — легко.
Ценность: средняя (стример не отрывает рук от игры).

### 2.12. Импорт/экспорт конфигов, «community commands» — ЛЕГКО
SB: копирование триггеров/суб-акций в base64-строку; гигантская библиотека community-imports.
MIU: репозиторий команд сообщества. Наш формат — JSON, кнопка «Экспортировать команду»
(строка/файл) и «Импортировать» — легко и создаёт экосистему вокруг бота.
Ценность: высокая в перспективе (шаринг пресетов фан-команд, мем-паков).

### 2.13. Симуляция и тесты — ЛЕГКО (частично есть)
Сохранить наш подход и добить: SB Test Trigger с кастомными аргументами, Simulated Events,
последовательность «прогнать событие с подменными данными в чат И в оверлей» — у нас есть кнопка
«Тест»; MIU — Play у каждой команды и действия + Command History (cancel/replay — см. §11.6).
Ценность: высокая для разработки собственных сценариев.

## 3. Экономика (Currency / Rank / Inventory / Stream Pass / Redemption Store)

### 3.1. Начисление валюты с бонусами и «накопительным» поведением — ЛЕГКО
MIU: валюта капает только пока стрим в эфире; бонусные множители сабам/модам; бонусы за события
(фоллоу/хост/саб/донат); «инактивность-таймаут» (перестать капать после X мин молчания юзера);
периодический сезонный сброс; «ретроактивная выдача» (начислить за всё прошлое watch time);
импорт/экспорт данных; «primary currency» для игр; лимит int32 (≈2.1 млрд).
У нас: просмотр (Get Chatters) + бонус за сообщение. Добавить множители ролям и
«инактивность-таймаут» — легко (абсолютный минимум кода). Сезонные сбросы — легко.
Ценность: высокая (зритель, промолчавший 10 минут, перестаёт фармить — экономика здоровее).

### 3.2. Топы, позиции, форматированные числа, «общая сумма по всем» — ЛЕГКО
MIU: `$top10points`, `$topX...`, `$userpointsposition`, `$pointsalltotal`, display-формат «20,000».
У нас есть `!топ-5`. Расширить `!топ N`, позицию юзера, сумму — легко. Ценность: средняя.

### 3.3. Ранги (Rank) по порогам очков — ЛЕГКО
Пользователь копит очки (обычно watch time) и получает названия рангов на порогах
(«Новичок < 10ч < Завсегдатай...»). Команды могут требовать ранг (и выше/ниже/точно).
У нас всё считается. Хранение + подстановка `{ранг-ник}` — легко.
Ценность: высокая (бесплатный престиж, повод поздравлять в чате, фильтр команд).

### 3.4. Инвентарь + магазин (buy/sell) + торговля между юзерами — СРЕДНЕ
MIU: предметы (предельный запас per user, «max amount»), магазин `!shop buy <предмет> [N]` /
`!shop sell ...`, трейд-рукопожатие в 3 шага (`!trade Ник Предмет N` → оффер → `!trade` = accept),
лимит 60 сек, одна активная сделка. Вся механика — чистый чат, никакого Twitch API.
У нас есть баллы + мем-магазин (одноразовые). Инвентарь (data/inventory.json) — средне (модели
предметов, UI, трейд-стейт-машина). Ценность: высокая для мета-игры сообщества, но не first priority.

### 3.5. Stream Pass («battle pass» канала) — СРЕДНЕ (упрощённый вариант — легко)
MIU: сезон с датами, уровни по очкам, точки начисления (просмотр/события), команды награды на уровень.
У нас: поверх рангов — уровни + разблокировки = периодические ивенты «месяц за баллы».
Ценность: средняя; механизмы дублируют ранги — можно урезать.

### 3.6. Redemption Store (магазин «услуг» с ручным подтверждением) — СРЕДНЕ, ОЧЕНЬ ЦЕННО
MIU: товары с количеством (и авто-восстановлением запаса на старте бота), требования на покупку,
«auto-redeem» (выполнить сразу) или «manual» (напомнить стримеру: `!redeem Ник` подтвердит самую
старую покупку). Наш мем-магазин — частный случай. Обобщить до «товаров с запасом
+ ручным исполнением» (например, «выбери следующий уровень», «10 отжиманий») — среднее.
Ценность: очень высокая — самый честный формат взаимодействия «зритель платит → стример делает»,
без channel points (которые у нас сейчас недоступны, см. §10.1).

## 4. Мини-игры (18 шаблонов MIU — все чисто чатовые)

Общая механика MIU: каждая игра — свой набор подкоманд и таймауты, роли для старта/ответа,
переменные `$gamebet`, `$gamepayout`, `$gamewinners`; валюта подключается автоматически.
**Все игры реализуемы на чистом Node: нужны только чат (read/write) и наши баллы.**
Ограничение — только рейт-лимиты сообщений: групповые игры надо укладывать в 2–4 сообщения
(собрать ставки одним сообщением, итог — одним-двумя).

| Игра | Поведение (по докам MIU) | У нас |
|---|---|---|
| **Bet** | Мод открывает ставку с вариантами (`!bet`); зрители ставят (`!bet <вариант> 100`); мод объявляет верный вариант — банк делится/выплачивается корректным | Средне; уже в ROADMAP фазе 3 — идеально ложится |
| **Duel** | `!duel <ник> 100` — вызов, победитель забирает ставку проигравшего | Легко; ROADMAP фазы 3 |
| **Heist** | Один стартует групповой набег, каждый ставит свою сумму; у каждого свой шанс успеха/провала | Легко-средне; классика (сюжетные строки приветствуются) |
| **Roulette** | Групповая: ставят на число/имя из диапазона; выигравшим — возврат с профитом | Легко |
| **Russian Roulette** | Все ставят одинаковую сумму, победители делят банк поровну | Легко |
| **Hot Potato** | Тикающая «бомба» передаётся между юзерами, у кого взорвалась — проиграл | Легко; отлично смотрится в оверлее |
| **Spin / Slot Machine** | Случайное число → исход по таблице вероятностей; за исход — выплата и/или выполнение команды | Есть (наше колесо = Spin с весами); слоты-3-символа в оверлей — легко |
| **Steal** | Попытка украсть баллы у другого юзера | Легко (осторожно с балансом) |
| **Hangman** | Слово угадывается буквами; каждый промах — взнос в банк; последний угадавший забирает | Средне (словарь слов в файле) |
| **Word Scramble** | Открыта анаграмма; первый отгадавший в окно забирает банк | Легко (словарь) |
| **Trivia** | Вопрос из кастомного/онлайн-списка, ответы цифрами в чат, вернувшим — выплата | Средне (список вопросов) |
| **Bid** | Аукцион: перебить ставку минимум +1, при перебое вернуть предыдущему; по таймауту — забрал топ-ставку | Легко |
| **Hitman** | Все вносят в банк; в чате объявляется «имя киллера»; кто первый его напишет — забирает банк | Легко |
| **Lock Box** | Банк-сейф: промах = взнос + подсказка; верный код = всё | Легко |
| **Coin Pusher** | Внесение монет в «пушер»: минимум для срабатывания, процентный payout | Средне |
| **Volcano** | «Вулкан» в 3 стадии; на 3-й стадии каждый взнос может вызвать извержение — джекпот внесшему + сбор монет для всех | Средне (многоэтапный стейт) |
| **Treasure Defense** | Командная игра с королём/рыцарями/ворами — король выбирает участника: рыцарь — команда делит банк, вор — воры | Средне |
| **Duck/Chat games** | У SB тоже есть «Present Viewers» Get Random chatter — для мгновенных розыгрышей | Легко |

Приоритет по ценности для стримера: Bet → Duel → Heist → RR → Hot Potato → Steal → слоты/спин
→ Hangman/Scramble/Trivia → остальное по вкусу. Первые пять закрывают 90 % спроса.

## 7. Оверлеи и виджеты

У нас есть база (SSE-шина, алерты событий, мемы, звуки, анимации). Идеи из MIU Overlays:

### 7.1. Несколько overlay-эндпойнтов — ЛЕГКО
Разные URL (`/overlay`, `/overlay/brb`, `/overlay/wheel`) — разные наборы виджетов
(например, отдельный оверлей для сцен «перерыв»). Реализация — отдельные страницы по роуту.
Ценность: средняя.

### 7.2. Виджеты-компоненты (главная жила MIU) — ЛЕГКО–СРЕДНЕ
- **Event List** — лента последних событий (фоллоу/саб/донат эквиваленты) с автостарением — ЛЕГКО;
- **Leaderboard** — топ по валюте/watch time на экране — ЛЕГКО;
- **Goal** — прогресс-бар цели (фолловеры/подписчики за стрим; стартовое значение из Helix +
  дельта по нашим событиям) — ЛЕГКО;
- **Stream Boss** — босс с HP по оверлею, зрители уменьшают HP баллами (`!босс N` = урон) — СРЕДНЕ;
- **Persistent Timer** — виджет-обратный отсчёт для челленджей, паузить/добавлять
  время командой — ЛЕГКО–СРЕДНЕ;
- **Wheel** — визуальная прокрутка колеса (наше колесо уже пушится в оверлей; сделать
  красивую анимацию вращения) — СРЕДНЕ;
- **End Credits** — титры в конце: кто был на стриме (топ участников, новые сабы, фолловеры),
  скролл со звуковым сопровождением — СРЕДНЕ (SB имеет аналогичный встроенный Credits);
- **Chat widget** — эмоуты/сообщения чата на экране (только эмодзи) — ЛЕГКО;
- **Persistent Emote Effect** — «дождь/взрыв эмодзи» из сообщений, с лимитами на количество — ЛЕГКО;
- **Poll** — визуализация голосования — ЛЕГКО (наши ставки = голосование);
- **Text/Label/Image/Video/YouTube/HTML** — произвольные виджеты с позиционированием
  (9 позиций/проценты/пиксели/рандом), entrance/exit-анимации, Duration — у нас есть аналоги
  для мема; обобщение «покажи картинку/видео по команде» — ЛЕГКО;
- **Custom widget** с пользовательским HTML/CSS/JS + вызов JS-функций из команд
  («Run Widget Function имя(параметры)») — СРЕДНЕ (песочница/безопасность), но именно это
  делает оверлей бесконечно расширяемым без правок ядра — у нас роль этой кнопки играют модули.
Ценность: Event List, Goal, Leaderboard, Stream Boss, титры — из «wow»-набора, который
создаёт «большой стрим» даже на 10 зрителях.

### 7.3. Динамические визуалы командой — ЛЕГКО
MIU Overlay Action: текст/картинка/видео/YouTube/HTML/таймер с длительностью и позицией по
случайным координатам. У нас мемы — частный случай; обобщить «послать в оверлей {type: text|image
|video|emotes, duration, position}» командой/модулем — легко. Ценность: высокая.

### 7.4. HTML Overlay поверх рабочего стола — СРЕДНЕ–ТЯЖЕЛО (зависит от сетапа)
SB поставляет отдельное нативное приложение-оверлей поверх всех окон: «splat», картинка,
эмодзи-дождь НА ЭКРАНЕ СТРИМЕРА (не в OBS). Повторить браузерной страницей нельзя поверх
fullscreen-игры. Обходной путь у нас — виджет-оверлей в OBS поверх игрового захвата
(работает в borderless-режимах). Ценность: средняя (эффект «осязаемого» действия наград).

### 7.5.LAN/multi-PC — ЛЕГКО (конфиг)
У нас сервер слушает 127.0.0.1. Для двухкомпьютерного сетапа — флажок «слушать LAN» в настройках
(с предупреждением безопасности). Ценность: средняя.

## 9. OBS-интеграция

  зависимости не нужны**; авторизация — challenge/salt + SHA-256 (node:crypto). Значимо упрощает:
  фаза 8 = СРЕДНЕ, не «тяжело».
- Сценарии по их докам для нас:
  - смена сцены по команде/событию («!brb» → сцена «AFK», рейд → сцена «Ending») — легко;

    но «Recording Started» можно использовать для мод-логов; Replay Buffer Saved →

  - Source Visibility как «награда» (за баллы включить звук смеха как источник) — легко.
Ценность: очень высокая; у SB это главная причина «быть комбайном».

## 10. Channel Points, Bits и прочие Twitch-события

### 10.1. Channel Points Redemption — НЕЛЬЗЯ в текущей архитектуре; СРЕДНЕ после расширения
Факты (Twitch docs): подписка `channel.channel_points_custom_reward_redemption.add` требует
скоуп `channel:read:redemptions` (или manage) — **только бродкастер**; EventSub WebSocket
может подписываться только на события «своего» токена → нужен **отдельный вход стримера**
(Streamer-аккаунт у SB/MIU обязателен именно поэтому; SB дополнительно требует пересоздать
награды «под ботом», чтобы владеть ими и управлять).
Что даёт: reward→действие (у SB: награды со счётчиками, max per stream/user, global cooldown,
pause/enable, группы; MIU: reward→команда, только custom-награды, срабатывание в момент покупки
(не при подтверждении!), upgrade статуса fulfillment/cancel только для созданных ботом наград).
Лимит Twitch: **50 кастомных наград на канал**.
Наша рекомендация: делать фазу 6 после появления «опционального входа бродкастера»
(стример логинится в панель отдельной кнопкой; токен хранится так же локально);
или замещать Redemption Store (§3.6) — у него нет лимитов и скоупов вообще.

### 10.2. Bits (cheer) — НЕЛЬЗЯ без токена бродкастера
EventSub `channel.cheer` требует скоуп `bits:read`, который выдаёт только сам стример.
У SB/MIU фичи на битсах: фильтры-диапазоны («100–500 бит → отдельное действие», точные суммы
с приоритетом), lifetime-статистика юзера. Для нас: после добавления бродкастер-входа — ЛЕГКО;
сейчас — нельзя. Совсем облако-аналогов (StreamElements TS-события) тоже нет.

### 10.3. События, доступные нам уже сейчас (только скоупы/подписки добавить) — ЛЕГКО:
- **пакет chat-notification** (у нас уже есть подписка): mass-gift (community_sub_gift),
  gift bomb (собственный фильтр: 5+ подарков → одно сообщение вместо спама — приём MIU:
  «Mass Gifted Subscriptions Filter Amount»), pay-it-forward, prime upgrade, bits badge tier,
  modiversary, **watch streak** (стрика просмотра) — поздравления и оверлей-пуши;
- **Расходящийся рейд** (outgoing raid completed) — «мы ушли к X» — есть через EventSub;
- **Shoutout received** (нам кинули SO) — триггер, модераторский скоуп — легко;
- **модерация-события** — см. §10.4;
- **stream title/game update** (channel.update — публичная, без спец-скоупа) — у нас !game/!title
  читает Helix по требованию; подписка на update — легко;
- **Hype Train** — `channel:read:hype_train` — ТОЛЬКО бродкастер (рано или поздно они
  откроют модераторам? — не факт; пишем честно: нужен бродкастер-вход).
### 10.4. Модерация-события и действия — ЛЕГКО–СРЕДНЕ (мы модератор):
- бан/таймаут/разбан (события) — moderator-скоупы;
- «сообщение удалено», «чат очищен»;
- warn (требует новый скоуп `moderator:manage:warnings`);
- shield mode begin/end (`moderator:manage:shield_mode`);
- unban requests (created/approved/denied) — модераторские скоупы;
- automod message held — отдельный automod-скоуп;
- VIP/manage — уточнить скоупы (частично модераторские);
- Модераторские действия API: удалить сообщение, таймаут/ban (moderator:manage:banned_users),
  purge, slow/emote/follower/sub-only режимы (`moderator:manage:chat_settings`).
Реализация — легко (ближе к рутине), но нужен перевход бота с расширенным скоуп-листом.
После этого доступна вся **автомодерация MIU** (§11.3). Ценность: высокая
(«умный мод» — киллер-фича для маленьких каналов).

### 10.5. Чего не будет и у них без токена бродкастера / вообще
- Создание/управление наградами и poll/prediction (`channel:manage:...`) — бродкастер;
- Запуск рекламы (`channel:edit:commercial`) и «upcoming ad» (`channel:read:ads`) — бродкастер;
- Charity / Goals (`channel:read:goals`) — бродкастер;
- Hype Chat — в MIU событие задекларировано, но **фактически не работает** (их же признание:
  «действует только как определение в коде») — честно вычёркиваем у всех;
- Whispers — верифицированные боты только (у нас в README уже).

## 11. Модерация (по MIU Moderation + SB Moderation-триггеры)

### 11.1. Фильтры слов — ЛЕГКО
- Filtered (удалить) и Banned (удалить + бан) списки слов/фраз; срабатывание по границам слова
  (наш взгляд: `"smoking weed"` найдёт, `"IAmSmokingWeed"` — нет) — берём приём
  word-boundary, но осторожно с кириллицей и комбинаторикой;
- «Community list» — готовый строгий список для family-friendly (у MIU локальный текстовый
  файл) — легко подключить словарь;
- исключения по ролям (выше роли — не трогаем).

### 11.2. Text-модерация — ЛЕГКО
- Max caps (кол-во или %), max symbols/punctuation/emotes (кол-во или %),
  блок ссылок (детект URL), — всё на глазах наших messages-обработчиков; правила только
  для сообщений длиннее N символов — берём их же («меньше 5 символов — не проверяем»).

### 11.3. Strikes-система — ЛЕГКО
Три страйка → таймаут (настраиваемая команда: предупреждение в чат / таймаут / бан);
страйки видно по `{страйки-ник}`, сброс модом. У MIU это кастомизируемые команды, у нас —
модуль. Ценность: высокая — мост между ручным модером и жёсткими санкциями.

### 11.4. «Участие в чате» (Chat Participation) — фильтр входа — ЛЕГКО–СРЕДНЕ
- Требования к участнику: возраст аккаунта (1 час … 1 год), watch time (10 мин … 10 часов),
  роль (фолловер/саб/мод);
- Реализация: возраст по /users, watch time по нашим данным; блок-сообщение
  на команду/молчание/удаление сообщения — легко.

### 11.5. Follow-event moderation — ЛЕГКО
Отличный приём: очередь фоллоу-приветствий с лимитом (не больше N подряд) — раз
фоллоу-спамом не убить чат. Мгновенно реализуемо в fire().

### 11.6. Command History (MIU) — СРЕДНЕ
Журнал выполненных команд: что завершено/выполняется/в ожидании, причина провала,
cancel/replay. У нас — расширение системного лога панели до уровня «дебаг-консоли
стримера» (вместе с SB Action History — история действий с инспекцией переменных —
их главный совет новичкам «смотри переменные в history»). Ценность: средняя (для нас,
разработчиков, — высокая).

## 13. Аудит и статистика чата / юзер-база

У MIU Users page: подробный профиль на каждого:
- watch time (часы/минуты), сколько стримов просмотрено, когда последний раз виделся (last seen),
- всего сообщений, всего команд, сколько раз тегнут (кто-то упомянул @ник);
- подписки (месяцы, streak, сколько подарил), bits lifetime, донаты lifetime (у нас донат-каналов нет);
- страйки модерации; заметки модов о юзере ($usernotes); кастомный титул;
- **кастомные команды для одного юзера** (только он может запускать);
- **кастомная entrance-команда** (что выполнится при первом сообщении юзера);
- exemption (не участвует в рандомах/экономике);
- поиск/фильтры, импорт/экспорт CSV.

Реализуемость — ЛЕГКО по нашим данным: счётчики вешаются в существующие обработчики
(chat.message, tick+Get Chatters, события). Топ-идеи для нас по ценности:
1. **watch time + last seen** (основа для welcome-back строк «{user}, давно не виделись!») — легко;
2. **статистика сообщений/команд** — легко;
3. **заметки и титулы** (переменная `{титул}` в приветствиях) — легко;
4. **кастомная entrance-приветствие per-user** — легко (user entrance = первое сообщение
   в стриме; MIU различает first message/first detected);
5. **экспорт CSV** для оверлея «топ недели» и постов-итогов — легко;
6. **$top10time / top10 субов / топ битсов** — легко с нашими счётчиками (битсы — после
   бродкастер-входа);
7. «Аудит чата» шире юзеров: активность по часам, пиковые часы, статистика эмодзи и длина
   сообщений — легко, если сохранять дневные агрегаты; отвечает стримеру на вопрос
   «когда чат живее всего». Ценность: высокая.

## 14. Прочее стоящее

### 14.1. File Folder Watcher — триггеры на файлы и процессы — ЛЕГКО, недооценённая фича
SB: событие «файл создан/изменён/удалён» + File Tail (следить за хвостом лога). Добавка —
триггер «процесс запущен/остановлен» (для нас — поллинг tasklist через модуль; допустимо,
без зависимостей). Кейсы: счётчик смертей в игре из её лога, «захват видео готов»,
«стример вышел в меню» → смена сцены OBS. Реализация — fs.watch + модуль. Ценность: высокая
для игр с логами (Hades, Slay the Spire...); клей между игрой и ботом без инжектов.

### 14.2. Web Request Action — СРЕДНЕ, осторожно
И MIU, и SB умеют HTTP-запросы из команд (и даже webhook-триггеры: donation-сервисы).
У нас это `fetch` в модулях — уже можно. Фича «команда с URL» из панели — делаем только
в виде **модуля**, не как универсальную подстановку `{fetch:...}` в кастомных командах
(инъекция/абуз). Ценность: средняя.

### 14.3. Discord — уведомления через webhook = ЛЕГКО; полноценный бот = ТЯЖЕЛО
Discord webhook — просто POST JSON (заголовки embed): «стрим начался», «новый саб»
в канал — легко сделать без зависимостей. Полноценный Discord-бот (gateway websocket) —
вне Twitch-фокуса, тяжело, не надо. Ценность: средняя.

### 14.4. Mass-gift фильтр — ЛЕГКО (см. §10.3) — уменьшает спам-грязь в чате; берём.

### 14.5. Gift Bomb / очередь алертов — уже есть (SSE-очередь), расширить приоритетами
(сабы важнее мемов, рейды вне очереди) — легко.

### 14.6. Import/экспорт пользовательских данных (MIU CSV) — легко; полезно для миграции
с других ботов (PhantomBot points.csv...).

### 14.7. MCP-сервер/HTTP API (MIU Developer API) — у нас HTTP API панели уже есть;
задокументировать = позволить скриптам/агентам управлять ботом. Ценность: средняя
(мы в 2026: локальный API популярной темы). Легко.

## 15. Что НЕЛЬЗЯ повторить в нашем стеке (и почему)

1. **Whisper-команды и TTS-в-виспере** — Twitch запрещает ботам без верификации; никого
   в этом винить нельзя, лимит платформы (SB упирается туда же).
2. **Bits-события, Hype Train, создание/подтверждение channel points наград, poll/prediction
   management, запуск рекламы, charity/goals** — только через токен бродкастера.
   В нашей архитектуре «только бот-модератор» — недоступно (нужно второе OAuth-подключение
   стримера; технически можно, но это отдельное архитектурное решение и политика доверия).
3. **Оверлей поверх рабочего стола стримера** (SB HTML Overlay App) поверх фулскрин-игры —
   невозможно браузерной страницей без нативного приложения (выходим из «нулевых
   зависимостей»).
4. **Облачные TTS-голоса** (Amazon/Brian, Azure, Google, клоны голосов TTS.Monster) —
   платные ключи/аккаунты и внешние сервисы; мы по принципу локально и без зависимостей
   ограничены системными голосами (Windows SAPI через speechSynthesis).
5. **Мультиплатформенность** (YouTube/Kick/Velora в MIU, YouTube/Kick в SB) — у них
   это их лозунг «один бот на все платформы»; мы принципиально Twitch-only (документированные
   публичные API Twitch). Не «нельзя» в принципе — вне миссии.
6. **Голосовое управление стримера через системный распознаватель Windows (SB)** —
   частично можно повторить через браузер (см. §12.2), глобальный хоткей — только
   с нативным приложением.
7. **Официальные интеграции донат-сервисов** (Streamlabs/Ko-fi/Tipeee..., merch: Shopify,
   Fourthwall) — это партнерские интеграции с токенами этих сервисов; через webhook
   (у нас есть HTTP-сервер!) — можно средне; из коробки «как у них» — не бесплатно и не локально.

## 17. Рекомендации (кратко)

1. **Фазы ROADMAP подтверждаются**: ставки (3), цитаты (4), TTS (7), OBS (8) — приоритет
   соответствуют их опыту сообществ. OBS технически проще, чем мы думали (нативный WebSocket Node 22).
2. Быстрые победы из «легко»-списка (№1, 2, 11–13, 16, 19, 20) — всего несколько дней кодинга.
3. Экономика: сначала **Redemption Store** (без лимитов Twitch и 50-наград-капа), потом —
   channel points, если появится желание вторым входом расширить.
4. Дизайн команд вперёд: наши фан-команды уже почти = MIU Commands; расширять в сторону
   Requirements (стоимость, кулдауны пер-юзер, threshold), не усложняя UI.
5. Автомодерация — самый большой пробел с точки зрения ценности/трудозатрат: мод-скоупы
   (перевход) + один модуль правил.
6. Не делать: мультиплатформу, облачный TTS, донат-интеграции, HTML-оверлей на десктопе,
   полноценный Discord-бот — вне фокуса локального Twitch-бота без зависимостей.
